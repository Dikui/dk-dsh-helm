# Swarm · 会话内的多成员协作黑板

Swarm 让同一棵 DSH 子代理树里的成员围绕一个持久黑板协作：成员在频道发帖，不必把每一段对话都塞进父会话上下文；需要某个同伴时用 `@` 呼唤。它是独立安装包，不依赖 Boost 或 Teamwork。

## 试用前

在测试 profile 的插件管理页添加本目录或本地安装包。使用支持本地子代理、工具和 `storageDomain` 的根会话；安装包针对 DSH `0.2.2-rc.5`。建议先在可丢弃的工作区里派一个成员做只读任务。共享工作目录并非沙箱，不要给未信任的模型实际写权限。会话能创建或唤醒多少成员仍受 Host 限制。

## 五条命令走一遍

在同一根会话中逐条发送。例子只派一个只读任务，避免多个执行者改到同一文件：

```text
/swarm init 边界检查
/swarm goal 找出并解释一个尚未覆盖的边界条件
/swarm add scout 只读检查当前工程的输入校验，先回帖报告，不修改文件
/swarm post @scout 请在主频道列出能复现问题的最小输入
/swarm status
```

成员调用 `read_board` 阅读对自己可见的帖子，调用 `post_message` 公布结果；已经读完时调用 `swarm_wait` 结束当前回合，而不是循环等待。`@name` 是门铃，不是普通抄送。`/swarm finish` 停用团队成员并保留黑板；不会撤销成员已经写入的文件。`read_board` 按最终渲染的 JSON 分页（`hasMore` 为 true 时继续读，单篇合法帖子即使转义后超过上限也会完整返回），无参数 `/swarm finish` 会先取消并等待同一根会话上正在启动的成员，再停用剩余名单。

## 按需指定模型与余额预警

`/swarm add <名字> --model <provider/model> --fallback <另一个 provider/model> -- <任务>` 显式指定主模型和一次性备用；不传 `--model` 仍继承 lead。模型 ID 可以包含 `/`，两个路由都必须获得当前会话的子代理路由授权并在宿主可用。确定的额度耗尽才尝试切换；普通限流不是余额，不能据此推算“还剩 10%”。续跑沿用同一成员、历史和工作目录，开启新回合，不重放旧工具调用。收到宿主明确的额度耗尽错误时，没有备用、备用未获授权或切换失败都会暂停该成员并通知 lead；普通限流累计 3 次才暂停，不消耗备用。

`/swarm quota` 由根会话查看 **DeepSeek 一方账号**提供的真钱包金额或不可用原因，不是任意模型服务商的额度查询。`/swarm quota watch CNY 5` 表示当人民币**充值钱包**余额不高于 5 元时提醒；也可用 USD。监控是显式开启、按黑板保存的；有可接收通知的 lead 和未停用成员时，每分钟检查一次，不用模型。不同币种、赠送钱包不相加，不知道金额时不报零，不因余额提醒自动换模型。`/swarm quota off` 关闭。宿主重启后，仍低于阈值可能再次提醒。

## 并行修改同一个 Git 仓库

```text
/swarm add coder --worktree -- 修改解析器，运行相关测试，提交后报告 commit
/swarm status
```

成员从 lead 当前分支的**已提交 HEAD**启动，独立工作树不带入 lead 的未提交改动；它隔离文件修改，不是权限沙箱。不传 `--worktree` 仍共享目录。lead 审阅提交并验收后执行：

```text
/swarm kill coder
/swarm merge coder
```

`kill` 停用成员，不删除成果。`merge` 只向派工时记录的 lead 分支快进交付，黑板保存已交付的 commit；不替你运行验收或创建合并提交。成员仍可运行、仓库/分支不匹配、目标或成员有未提交改动都不交付。两个同基线成员先后提交时，第二个常常已分叉：保留分支和工作树，按返回的提交/分支手工审阅、整合；不会强推、强制清理或自动消解冲突。需要宿主 Git、工作目录和策略后端；能力不足时拒绝隔离请求，不偷偷改为共享目录。

## 怎样读黑板

在当前根会话使用 `/swarm view`，或打开右栏的新标签指南 → **Swarm 黑板** → **读取最新快照**。四个视图来自同一份 Host 快照：

- **概览**：看目标、任务、讨论线与成员数量。
- **黑板**：按频道过滤最近消息，保留作者和 `#seq` 编号。
- **成员**：查看每个成员的角色、状态、消息游标与未读指标。
- **呼唤关系**：拖动消息序号，查看这一小段历史里的定向呼唤，不是完整聊天记录或实时网络拓扑。

读取快照不派工、不发帖、不唤醒成员；它会留下普通的命令执行记录，因此页面不会自动轮询。切换会话后需重新读取。界面不可用时，命令仍可独立工作。

## 运行边界

- 黑板状态保存在 DSH 配置的存储后端。对同一根会话的更新按顺序提交，写入成功后才应尝试发送门铃。**已写入**不等于**已投递**，而投递成功也不代表对方已经读过。
- 空闲成员不应通过连续模型调用等消息；额度暂停、容量不足、子会话不可恢复与成员被停用需要区分。重启能读回黑板，不代表自动复活每个历史进程。
- 不会因为成员退出就强删 Git 分支或脏工作树，不提供多 Host 对同一个存储目录的并发写保证。

## 验证

安装依赖后运行 `npm test`。可选真实存储测试通过 `DSH_TEST_RUNTIME` 指定本机安装的 DSH 解析清单，验证两个完全独立的 Cordis Host 能在临时 JSON 后端上保存、关闭、重新读取同一个会话记录。工作树集成测试在临时 Git 仓库使用真实的宿主文件和子进程服务，验证修改隔离、停用成员和快进交付；额度测试使用模拟钱包及请求错误，不扣费。侧栏可在无浏览器条件下检验注册、绑定与失败路径；这些测试不等同于视觉验收或真实模型协作实测。
