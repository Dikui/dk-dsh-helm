# Swarm · 会话内的多成员协作黑板

Swarm 由一个 DSH 根会话管理持久黑板。原生子代理在频道发帖，用 `@` 唤起同伴，不必把每一段对话都塞进父会话上下文；其他机器或 CLI 可经单独授权的席位参与，靠显式同步收发。它是独立安装包，不依赖 Boost 或 Teamwork。

## 试用前

在测试 profile 的插件管理页添加本目录或本地安装包。使用支持本地子代理、工具和 `storageDomain` 的根会话；安装包针对 DSH `0.2.2-rc.5`。建议先在可丢弃的工作区里派一个成员做只读任务。共享工作目录并非沙箱，不要给未信任的模型实际写权限。会话能创建或唤醒多少成员仍受 Host 限制。

## 五条命令走一遍

在同一根会话中逐条发送。例子只派一个只读任务，避免多个执行者改到同一文件：

```text
/swarm init 边界检查
/swarm goal 找出并解释一个尚未覆盖的边界条件
/swarm add scout 只读检查当前工程的输入校验，先回帖报告，不修改文件
/swarm post @scout 请在主频道列出能复现问题的最小输入
/swarm status
```

## 会话级开关

根会话的模型菜单里有一行 **Swarm** 开关（Web/桌面端）。新会话默认关闭：尚未建板时不会向模型注入 `swarm` 工具或提醒；打开时才按需创建黑板并注入工具。关闭会隐藏根会话的 Swarm 工具、停止根会话的提醒和门铃，但保留黑板与成员，成员自己的 `post_message`/`read_board`/`swarm_wait` 仍可用；再次打开会补送根会话尚未投递的唤醒。开关只影响当前根会话，子会话不显示；首次建板仍可使用 `/swarm init`。

成员调用 `read_board` 阅读对自己可见的帖子，调用 `post_message` 公布结果；已经读完时调用 `swarm_wait` 结束当前回合，而不是循环等待。`@name` 是门铃，不是普通抄送。`/swarm finish` 停用团队成员并保留黑板；不会撤销成员已经写入的文件。`read_board` 按最终渲染的 JSON 分页（`hasMore` 为 true 时继续读，单篇合法帖子即使转义后超过上限也会完整返回），无参数 `/swarm finish` 会先取消并等待同一根会话上正在启动的成员，再停用剩余名单。

## 交付物与验收

自由发帖不用建任务；要追踪验收时，单独给成员一份交付约定。以下例子中，`submit` 由 scout 执行，`review` 由 lead 核查产物后执行：

```text
/swarm assign boundary scout "一份输入边界报告" "给出空输入的复现步骤和预期结果"
/swarm submit boundary v1 docs/boundary.md
/swarm deliveries boundary
/swarm review boundary 1 returned failed "v1 没说明空输入的预期结果"
/swarm submit boundary v2 docs/boundary.md
/swarm review boundary 2 accepted passed "已按 v2 步骤复现，预期结果与实际一致"
```

首轮就有验收条件的原生成员，可在派工时使用 `/swarm add scout --contract boundary "一份边界报告" "能复现空输入" -- 只读检查输入校验`，不需要先启动成员再补 `assign`。提交既支持版本加路径，也可单独给出 `--path docs/boundary.md` 或 `--commit <SHA>`；后者只记录引用，不会拉取或验证远程 Git 对象。

`/swarm deliveries` 分页列出任务；`/swarm deliveries <taskId>` 看判据、当前版本/路径和最新评审。模型可使用同名流程的 `swarm_delivery` 工具；成员只能看和提交自己的任务。编号是**任务内提交序号**，不是黑板帖子序号；重提后旧编号不能验收。lead 必须写明检查结果与依据，失败不能标为通过。它记录验收，不会打开成员给出的路径或执行命令。`done` 发帖、`finish` 停用、`merge` 快进都不等于验收。每板最多 128 份合约，保留当前提交、针对该提交的评审，以及重提之前最近一次退回的依据（`lastReturn`），不是完整审计日志。

若要让另一个评审者在不知道作者、看不到已有评语的情况下判断，可先给产物去掉署名，在独立会话只提供编号、产物和判据，收到初判后再由 lead 记录 `review`。黑板的 `monitor` 角色本身不提供匿名隔离；需要封存初判或执行独立检查，可另用同仓 [Boost](../boost/README.md#如何读结果)，不会随 Swarm 自动运行。

## 截止时间与静默提醒

```text
/swarm clock deadline 2030-06-15T17:00:00+08:00
/swarm clock silence 15
/swarm clock
/swarm clock off
```

两项默认均关闭，可分别用 `deadline off` 或 `silence off` 关闭。截止时间必须带 `Z` 或偏移量；静默窗口单位为分钟。仍有任务时，即使成员显示工作中，没有新帖子或交付进展也能提醒 lead；全员停等仍单独诊断。提醒由每三分钟一次的扫描触发，不是精确定时器，不判失败、不停进程。成功投递的同一事件去重；若发送后尚未保存回执就崩溃，重启后可能再次提醒。

## 按需指定模型与余额预警

`/swarm add <名字> --model <provider/model> --fallback <另一个 provider/model> -- <任务>` 显式指定主模型和一次性备用；不传 `--model` 仍继承 lead。模型 ID 可以包含 `/`，两个路由都必须获得当前会话的子代理路由授权并在宿主可用。确定的额度耗尽才尝试切换；普通限流不是余额，不能据此推算“还剩 10%”。续跑沿用同一成员、历史和工作目录，开启新回合，不重放旧工具调用。收到宿主明确的额度耗尽错误时，没有备用、备用未获授权或切换失败都会暂停该成员并通知 lead；普通限流累计 3 次才暂停，不消耗备用。

`/swarm quota` 由根会话查看 **DeepSeek 一方账号**提供的真钱包金额或不可用原因，不是任意模型服务商的额度查询。`/swarm quota watch CNY 5` 表示当人民币**充值钱包**余额不高于 5 元时提醒；也可用 USD。监控是显式开启、按黑板保存的；有可接收通知的 lead 和未停用成员时，每分钟检查一次，不用模型。不同币种、赠送钱包不相加，不知道金额时不报零，不因余额提醒自动换模型。`/swarm quota off` 关闭。宿主重启后，仍低于阈值可能再次提醒。

需要确认上游此刻能否响应时，lead 可显式执行 `/swarm probe <provider/model> --confirm-paid`。它只探测**一条获授权的路由**，发送固定短提示，不带会话内容或工具，不重试、不改路由、不派工；这一次请求**可能计费**。结果区分成功、额度、限流、容量、鉴权、超时等；成功不是未来容量保证，超时也不保证服务商没有计费。普通 `add` 不会自动做这个实测。

## 外部机器或其他 CLI 参与

外部成员不需要成为 DSH 子会话。Swarm 仍只有一个写黑板的 Host：外部 CLI 通过**独立席位信箱**读可见快照、排队发帖或提交版本，lead 明确同步后才有回执。插件不会启动远端进程、监听网络、分发凭据或同步代码。

1. 由管理员预先建立专用空目录：Host 用户拥有、权限 `0700`、规范绝对路径、祖先不可由非信任主体改写。根会话运行 `/swarm external add remote /absolute/private/swarm-mailboxes`，保存返回的 `mailbox` 路径。**不要共享整个基目录、工程目录或 DSH 配置目录。**
2. lead 执行 `/swarm assign report remote "提交报告" "列出来源"` 和 `/swarm external sync remote`。经受限 SSH 或保留 POSIX 权限和原子重命名语义的挂载，仅授权该成员访问自己的席位：读取快照和回执、写入其 `inbox`。不得授予修改席位根或父目录的权限；为收件目录配置磁盘配额。例如多用户 POSIX 环境中，基目录保持 `0700`，只把单个席位挂载给外部账号；席位目录及 `inbox` 均由 Host 拥有、属组为仅含 Host 与该账号的专属组，权限分别为 `2750`、`2770`。组继承使新文件 `0640` 可供双方读取；也可提供具有同等隔离性的管理员 ACL。不同席位不要共用拥有 Host 权限的账号。
3. 在同一席位的受限环境下使用包内 `bin/swarm-seat.js`，以 `SEAT` 指代该成员看到的绝对路径：

   ```sh
   node bin/swarm-seat.js "$SEAT" read
   node bin/swarm-seat.js "$SEAT" post '我开始核查来源' main
   node bin/swarm-seat.js "$SEAT" submit report v1 docs/report.md
   node bin/swarm-seat.js "$SEAT" ack <请求UUID>
   ```

4. lead 再执行 `/swarm external sync remote` 处理请求并刷新快照，然后用 `/swarm deliveries report` 验收。CLI 返回 `queued` 只是入队；`ack` 才表示 Host 已处理。为了在 CLI 回包前断线也能重试，可在请求方先生成并保存小写 UUID v4，在 `post` 或 `submit` 末尾加 `--id <UUID>`。重连后查同一个 ID 的回执，或用**同一 ID 和同一内容**重试；新的逻辑请求才用新 ID。省略 `--id` 时，妥善保存 CLI 返回的自动编号。快照只含该席位可见的最近 32 帖和自己的约定；不推进 DSH 原生已读游标。

   同一任务首次提交默认以序号 0 为起点；改版要先读取上次回执，再用新 UUID 指定 `--after <上次提交序号>`（放在 `--id` 之前）。例如 `submit report --commit 4f83abc --after 1`。若别人抢先更新或消息乱序，过时请求会收到 `STALE_SUBMISSION`，不会覆盖已有版本。单路径也可写作 `submit report --path docs/report.md`。

`pause`/`kill` 后 Host 拒绝该席位后续同步，无法收回已读取的数据或删除已排队文件；撤销 SSH/挂载权限、清理旧文件由管理员负责。每次同步最多扫描 256 个目录项、处理 32 个请求；遇到批量积压时可连续同步。闲置扫描位置 10 分钟后或 Host 重启会重置。磁盘保留最近 256 条回执，已过期的 `ack` 查询也可能显示 `pending`。黑板每席位至多记录 512 个已处理请求 ID（成功或业务拒绝），不会驱逐旧 ID 后重复写入；满额请停用旧席位，换新名字、新信箱，并为未完成工作另派任务。不支持所需文件权限语义的平台请在受限 POSIX 主机运行席位 CLI，不要放宽目录权限。

## 并行修改同一个 Git 仓库

```text
/swarm add coder --worktree -- 修改解析器，运行相关测试，提交后报告 commit
/swarm status
```

成员从 lead 当前分支的**已提交 HEAD**启动，独立工作树不带入 lead 的未提交改动；它隔离文件修改，不是权限沙箱。不传 `--worktree` 仍共享目录。lead 审阅提交并验收后执行：

```text
/swarm kill coder
/swarm merge coder
```

`kill` 停用成员，不删除成果。`merge` 只向派工时记录的 lead 分支快进交付，黑板保存已交付的 commit；不替你运行验收或创建合并提交。成员仍可运行、仓库/分支不匹配、目标或成员有未提交改动都不交付。两个同基线成员先后提交时，第二个常常已分叉：保留分支和工作树，按返回的提交/分支手工审阅、整合；不会强推、强制清理或自动消解冲突。需要宿主 Git、工作目录和策略后端；能力不足时拒绝隔离请求，不偷偷改为共享目录。

## 怎样读黑板

在根会话打开右栏的新标签指南 → **Swarm 黑板**。面板打开就会读取当前状态，之后自动更新，无须先发命令或点击刷新。四个视图共用同一份数据：

- **概览**：看目标、任务、讨论线与成员数量。
- **黑板**：按频道过滤最近消息，保留作者和 `#seq` 编号。
- **成员**：查看每个成员的角色、状态、消息游标与未读指标。
- **呼唤关系**：拖动消息序号，查看这一小段历史里的定向呼唤，不是完整聊天记录或实时网络拓扑。

实时接口仅供本机桌面端或本机浏览器的所有者在根会话使用；LiveShare 访客和开启远程访问的 Host 不开放此接口。面板只读，不执行会话命令、不调用模型，也不推进成员的已读游标。前台有黑板时约每 1.5 秒检查一次，尚未建板时约每 3 秒检查一次；窗口隐藏且已有黑板时降至每分钟，隐藏且无板时暂停。回到前台会立即追更，切换会话会重新读取。数据没变就不重绘；即使没有新帖，成员状态和计划的变化也会同步。

暂时断线时，面板保留最后一次成功读取的数据，提示重连并自动重试，也可手动立即重试。只想取一次快照或侧栏不可用时，根会话仍可手动执行 `/swarm view`；只有这种用法会留下普通命令记录。

## 运行边界

- 黑板状态保存在 DSH 配置的存储后端。对同一根会话的更新按顺序提交，写入成功后才应尝试发送门铃。**已写入**不等于**已投递**，而投递成功也不代表对方已经读过。
- 空闲成员不应通过连续模型调用等消息；额度暂停、容量不足、子会话不可恢复与成员被停用需要区分。重启能读回黑板，不代表自动复活每个历史进程。
- 不会因为成员退出就强删 Git 分支或脏工作树，不提供多 Host 对同一个存储目录的并发写保证。

## 验证

安装依赖后运行 `npm test`。可选真实存储测试通过 `DSH_TEST_RUNTIME` 指定本机安装的 DSH 解析清单，验证两个完全独立的 Cordis Host 能在临时 JSON 后端上保存、关闭、重新读取同一个会话记录。工作树集成测试在临时 Git 仓库使用真实的宿主文件和子进程服务，验证修改隔离、停用成员和快进交付；模型实测、额度测试使用模拟适配器、钱包及请求错误，不扣费。外部席位测试通过独立 CLI 进程读写真实临时信箱，覆盖断线重发、重启和旧提交拒绝；不代表已实测某个 SSH 服务、跨机挂载或第三方 CLI。侧栏可在无浏览器条件下检验注册、绑定与失败路径；这些测试不等同于视觉验收或真实模型协作实测。
