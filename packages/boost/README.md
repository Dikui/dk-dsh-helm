# Boost 独立复核 · DSH 插件

`/boost` 适合一个可用命令检查的代码任务：一个执行者在当前工作区实现，一个全新复核员先看你选的源码和 Host 实际取得的检查结果，提交不可改写的初判，然后才能看执行者的最终报告。一次命令只有这两个子会话，不会自动迭代、提交或回滚。

## 试用

在 DSH 的 **插件 → 添加插件** 中选择本目录（或使用本地打包文件）。在新的 **根会话** 使用允许原生 `bash`、`read` 的 preset，切到一个可丢弃的项目副本。安装会作用于整个 profile；建议先使用测试 profile。插件针对 `0.2.2-rc.5`，需要本地 `spawn`、角色 preset、原生工具执行器，且子代理深度至少为 1。使用父会话的模型路由，不绑定模型品牌。

例：项目已有 `src/clamp.js` 和 `test/clamp.test.js`，用一条多行消息发送（不要带代码围栏）：

```text
/boost 修复 clamp：小于 0 返回 0，大于上限返回上限，区间内保持不变；不要修改验收测试。
@file src/clamp.js
@file test/clamp.test.js
@check node --test test/clamp.test.js
```

只输入 `/boost` 或 `/boost --help` 可查看格式。`@file` 为 1–4 个相对工作区的文本路径，每行一个；`@check` 必须且只能出现一次，是**你授权实际执行**的一行前台命令。先检查命令、测试和输出中是否包含不宜发给当前模型的信息。源码建议包含实现和相关测试，不能仅凭一个退出码判断需求已满足。

## 如何读结果

- 先看实际检查的退出码，再看「封存初判 → 最终比对 → 执行者报告」。退出码非零即使两位模型都声称通过，也按失败显示。退出码零仅说明该命令通过，不代替复核员发现的问题或人工验收。初判封存不等于执行者报告已交付：若 Host 的 post-execute 策略阻止或替换了 `boost_reveal` 的最终内容，或复核员随后失败、没有产出，命令会失败，结果只保留已封存的初判并明确说明比对未完成，不会显示「最终比对」。
- 复核员不能浏览工作区或执行 shell。Host 在执行者结束后，通过父会话的 DSH 工具运行检查并取样文件：每个文件首 120 行且最多 6,000 字符，标准输出和标准错误各取末 3,000 字符。复核员看到的是有边界的证据包，可能遗漏未取样的缺陷。
- 初判在本次运行中封存；正常完成后初判和比对一起写入命令结果。不是防篡改审计系统，也不提供崩溃续跑。执行者与父会话共享工作区：工具白名单不是 OS 隔离，执行者也可能修改测试或把意见写进代码；重要验收应使用受保护的测试或独立工作副本。
- 缺少必要工具、取消、仅得到后台任务、未提交初判、空或超限报告都不会被当作成功。超时晋升的检查会尝试停止并报告 job id。失败/取消时先检查工作区改动再重试；同一 Host 上同一工作目录只接受一轮 Boost，其他程序或嵌套目录的写入不会被锁住。
- 当前只实现扁平 Boost，不含 Swarm 看板、Teamwork 调度、自动修复轮次或自定义浏览器面板。

## 开发检查

`npm test` 运行协议、角色和命令行为测试；`npm pack --dry-run` 查看发布内容。测试不需要模型凭据。源码快照、测试输出和模型报告均是待判断的数据，不是新的用户授权。
